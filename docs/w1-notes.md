# W1 复盘：最小闭环两次真实运行对比

场景：`"十一去成都4天，两人预算6000，爱吃辣但同伴不能吃太辣，要一顿火锅一顿苍蝇馆子，住春熙路附近"`
模型：glm-4.7（智谱 Anthropic 兼容端点）· 工具：高德官方 MCP + 自写 travel MCP（进程内 SDK MCP）

## 运行数据

| 指标 | Run 1（无 travel MCP） | Run 2（+travel MCP+prompt 规则） |
|---|---|---|
| 耗时 | 354s | 252s |
| 工具调用 | 19 | 23 |
| input tokens | 60,609 | 54,438 |
| output tokens | 7,490 | 6,071 |
| 成本（Anthropic 牌价折算） | $0.62 | $0.50 |
| 火锅推荐 | 海底捞（连锁保底解） | 翠孃孃老火锅·鸳鸯锅（扣住辣度矛盾） |
| 苍蝇馆子 | 钟晓敏冒烤鸭 | 明婷饭店（老字号，maps_search_detail 二次核实） |
| 交通/酒店价格 | 拍脑袋估算 | travel 工具报价（含 1.6 旺季系数），来源可溯 |

## Prompt 软约束修掉的问题（Run 1 → Run 2）

- ✅ 交通/酒店价格无来源 → 必须走 travel 工具，mock 标注透传到 warnings
- ✅ 正餐推荐纯套话 → 推荐理由扣住"一人爱辣一人不辣"（鸳鸯锅/可调辣度）
- ✅ 未声明出发地假设 → warnings 明确"假设上海出发"

## 软约束管不住的问题（Run 2 仍存在 → W2 Verifier 验收标准）

1. **到达日时间线冲突**：推荐 G1378 14:07 到成都，Day 1 却排了 07:30 熊猫基地。
   → 校验器规则：Day 1 首个活动开始时间 ≥ 大交通到达时间 + 缓冲。
2. **预算加法不闭合**：各天 dayCost 之和（含 1 晚房费）+ 交通 1868 + 另两晚房费 966 ≈ 5210 ≠ totalCostEstimate 5376。
   → 校验器规则：sum(dayCostEstimate) + 未入天的项 == totalCostEstimate（容差 ±1%）。
3. **就近吃饭规则被突破**：Day 3 上午武侯祠 → 午餐横跨约 6km 去北门明婷饭店 → 下午折回武侯祠旁的锦里。
   → 校验器规则：相邻两项间高德通勤时间 ≤ 排程预留时间；正餐与前一活动距离超阈值即打回。

**结论**：prompt 能修"没想到"，修不了"算不准"。确定性校验器（纯代码）是下一步的正确投入——这三条就是它的第一批测试用例。

## 已知局限（W1 范围内接受）

- 交通/酒店为确定性 mock 报价（结构真实、来源标注），W2+ 可换 12306/航班 MCP
- 营业时间未核验（高德 detail 有该字段，Verifier 接入时一并做）
- 单 Agent 结构，上下文所有检索结果混在主循环里（W2 拆子 Agent 的消融对比素材）
